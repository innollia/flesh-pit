# 1차 기획서를 보관하고 코드와 2차 문서를 기준으로 삼는다

사용자가 2026-11-07에 말했다. "개발 진척이 길어져서 기획은 무시해도 되는 단계에 도달했어. 보관 처리를 고려", "이거 아무래도 2차 기획문서를 만들고 내 이 결정들을 모으거나 기존 문서구조를 잘 활용해야 할듯".

## 결정

- `docs/spec/` 11장을 `docs/archive/spec-v1/`로 옮겼다. 내용은 고치지 않는다.
- 코드 주석이 옛 경로를 가리키므로 `docs/spec/README.md` 한 장을 남겨 보관 위치와 새 문서를 안내한다.
- 지금 기준은 코드와 `docs/design/`이다. 어긋나면 코드, `docs/design/`, 그 밖의 현행 문서 순서다.
- 옛 기획과 다른 다음 항목은 현재 상태가 기준이다: 문 상호작용 30°/1.6 m, 거울 전용 몸, 엔딩 버드뷰, 기획서의 등대 문장 삭제. 결정 0000의 "떨어지는 엔딩"도 버드뷰로 대체된다.
- `docs/design/`은 현재 게임을 적고, 행동 규칙은 `docs/business-rules.md`, 결정 근거는 이 폴더에 둔다. 작은 판정은 `docs/design/decisions-log.md`에 사용자 말과 함께 모은다.

## 수치 출처

- 04 경제의 현재 값은 `docs/design/economy.md`로 옮겼다. 원본은 코드 상수다.
- 09 보상 척도의 감사 표는 계산기가 쓰는 표라 `docs/design/economy.md`로 옮겼다. `reward_scale.py --write`의 대상도 그쪽이다. 척도의 방법과 대역은 보관본을 읽기만 한다.
- `reward_scale.py`가 근거 인용에 쓰는 04와 10은 보관본 경로에서 읽는다.
- 옮기는 김에 `tools/economy/params.json`의 조직 경도·재생 값을 바이옴 조직이 들어간 코드 값에 맞췄다. 어긋난 채로는 계산기가 표 쓰기를 거부했다.

## 버린 안

- 기획서를 제자리에서 계속 고치는 안: 코드와 어긋난 문장이 늘어서 기획서가 판정 기준 노릇을 못 했다.
- 코드 주석의 경로를 모두 고치는 안: 게임 코드를 여러 담당이 동시에 고치는 중이라 충돌만 늘고, README 한 장으로 같은 효과를 낸다.
