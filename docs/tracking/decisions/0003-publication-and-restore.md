# 단계 게시와 저장 복원

연속 재생 속에서 청크를 하나씩 즉시 게시하면 공유 경계가 벌어지고, 새 변경마다 배치를 다시 만들면 완료되지 않는다. 반대로 실제 과거 저장을 단계 게시만으로 복원하면 첫 화면에 살점이 없는 시간이 생긴다.

일반 굴착은 같은 밀도 스냅샷을 동결해 연결 그룹을 함께 게시하고 미게시 변화는 실제 임시 면으로 표현한다. 준비가 시간 예산을 소비하면 빌드를 다음 tick으로 넘기되 작업은 이어간다. 디스크 복원은 화면과 입력이 재개되기 전에 실제 메시·충돌을 한 번 전체 준비한다.

매 뜯기마다 전체 remesh하는 대안은 큰 세계의 비용을 입력에 묶는다. 모든 복원을 단계 게시만으로 처리하는 대안은 첫 렌더링 누출을 허용한다. 전체 재생 중단은 진행과 세계 위험을 바꾼다.

일반 실행의 제한된 예산과 단발 복원을 구분해야 한다. 과거 파일의 정확한 밀도뿐 아니라 첫 렌더프레임도 검사한다. 생성기 캐시는8192개로 제한하고 레이아웃 변경 시 비워 실제 수정 밀도와 섞지 않는다.
