D01 T5는 카메라 FOV를 166.67도로 늘리던 방식을 버리고, 플레이어 카메라를 따르는 90도 다섯 면(앞·좌·우·위·아래)을 등거리 어안 셰이더로 합성해 가로 200도를 그린다(`fp_fisheye_view.gd`). 조준·도달 거리·손은 기존 75도 카메라를 쓰고, 압사의 22% 시야 축소는 같은 비율로 어안에 적용된다. 어안이 그리는 프레임에만 원래 카메라의 cull mask를 0으로 두어 여섯 번 렌더하지 않는다. 검증은 사용자 저장을 쓰지 않는 `flesh-pit-restoration-` 격리 사본에서 표준 33개에 실제 입력·변이·먹기 게시·정산·메뉴를 더한 38개 묶음을 실행했다. 36개가 종료0, 실패 2개(`run_mutation_tests.gd` 4건, `run_settle_vent_tests.gd` 4건)는 변경 전 코드에서도 같은 항목으로 실패한다. 오디오 단독 검사는 178/0이다. 새 검사는 수정 줄을 빼면 실패하는 것을 확인했다. 중간 실행에서 밀도 캐시·보존 검사가 엔진 시작 직후 각각 한 번 180초 시간 초과로 실패했고, 같은 소스의 재실행과 최종 전체 실행에서는 통과했다. 사용자가 대화로 보고한 열린 환풍구 NPC 뒤 살점도 수정했다. 덕트 모델은 ±0.26m·높이 0.7m인데 지형은 ±0.30m·0.8m만 비웠고, 0.5m 격자가 환풍구 중심과 어긋나 살 표면이 덕트 안(x 방향 -0.20m, 천장 0.65m)에 생겼다. 비우는 공간을 모델에 한 칸(0.5m)을 더한 크기(`VENT_DUCT_HALF`, `VENT_DUCT_TOP`)로 넓혀 덕트에 닿는 모든 칸의 꼭짓점이 비게 했고, 이전 저장은 불러올 때 이 덕트 공간의 꼭짓점만 비운다(`_clear_vent_duct`). 밀도 캐시 검사에 "덕트에 닿는 칸에 살 꼭짓점 없음"과 저장 복원 후 같은 조건을 추가했으며 예전 크기로 되돌리면 두 항목이 실패한다. 960×540 확대 캡처 네 방향에서 덕트 안은 검은 어둠과 눈만 보인다. 이 이관 때문에 실제 과거 v5 저장의 "전체 밀도 정확 복원" 검사가 두 청크에서 실패했다. 검사를 지우지 않고, 덕트 꼭짓점은 0이고 그 밖의 모든 꼭짓점은 파일과 정확히 같아야 하며 덕트 청크에서는 실제로 비워졌는지를 확인하도록 바꿨다(666/0). 수정 뒤 전체 38개 실행에서 `run_oct02_tests.gd`·`run_restoration_t9_tests.gd`가 180초 시간 초과, 조직 도구의 압박 중 remesh 8ms 기준이 10.43ms로 실패했다. 그때 브라우저 보드 내보내기를 동시에 돌리고 있었고, 세 묶음 모두 단독 재실행에서 통과했다. 실제 렌더링 GUI 6개 묶음(`run_godot_render_checks.cjs`)도 종료0이다.

## 2026-10-05 실제 조작 재점검

게시 기준 `13cd8d5` 뒤 Desktop의 미커밋 Main 파일에서 복구된 이동 필터·후방 탈출·문 표적·정산 입력·눈부심 연결이 다시 빠진 것을 확인했다. 해당 파일은 공백을 제외하면 `12fc534`의 Main과 같았다. 원문을 별도 보존한 뒤 게시 기준으로 복원했다. 어떤 프로세스가 썼는지는 확인되지 않았다.

추가로 변기 표적의 V 안내, 일반 착석에서도 WASD/Space로 일어서기, 오른손으로 쥔 이빨을 NPC에 건네기, 최초 물내림 대사 및 만남·지급 이력의 저장을 수정했다. Space 굴착 상승은 4.5m/s이며 기존 하강 2.5m/s와 화장실의 점프 없음은 유지한다. 카나리아는 5.6초 동안 실제 캡슐을 눕혀 한 팔로 뒤지고 새 한 마리를 잡은 뒤 기존 팬티에 넣는다. 별도 주머니·띠·덩어리를 없애고 기존 천의 정점만 늘린다. 팔의 임시 변형은 종료 시 원래 메시로 복구하며 거울도 같은 손 목표와 천 변형을 사용한다.

마지막 동작 수정 뒤 기본 CPU 8개 묶음(655항목)이 실패·생략 없이 종료0으로 통과했다. 별도 실제 GUI 입력은 60항목/종료0이며 V 표시, NPC 지급·수령 및 파일 왕복, 문 다시 닫기, 일어서기, 카나리아 각 단계와 동작 이후 B를 확인했다. 정상 Main GUI 연결 212항목도 종료0으로 통과했으며 어둠 20초 이후 한 번의 밝은 귀환 눈부심과 문턱 왕복 시 추가 눈부심 없음, 실제 신경 조직 사망을 확인했다. 캡슐 압사 47항목, 이동 경계 33항목에서는 실제 짧은 후방 탈출과 전체 압사 제한 시간 이후 생존을 확인했다. 시도했던 압사 조건 완화는 기존 실제 압사 검사를 깨뜨려 철회했다. 원인 불명의 모든 사망 상황이 사라졌다고 이 장면만으로 일반화하지 않는다.

저장 검사 한 번의 180초 시간 초과는 실패로 남긴다. 같은 소스의 단독 저장 검사와 최종 기본 8개 묶음은 각각 종료0으로 재통과했지만 시간 초과의 원인은 특정되지 않았다. 종료 시 기존 ObjectDB/resource 잔류 경고도 남아 있다. 현재 기록은 과거 전체 33개 묶음을 다시 실행했다는 의미가 아니다.

화장실과 인터페이스를 갖춘 굴착 가능한 플레이 버전이다. 먹기·위장·정산·도구·변이·위험·소리·저장·바깥 엔딩의 코드가 있으며, 모든 게임 여정이 이번 검사로 완료 검증된 것은 아니다.

앞선 세 가지 지형 결함 수리 당시 통합 코드에서 node --test game/tests/run_godot_checks.cjs의 지형·기존 보존20개 묶음(4,212항목)과 node --test game/tests/run_godot_render_checks.cjs의 실제 렌더링6개 묶음이 모두 종료0으로 통과했다. 렌더링은 내부·경계·미게시·재생·과거 저장과 정상 입력을 함께 확인했다.

## 화장실 정상 플레이 복원 검증

복원 코드 1707def에서 최종 CPU 33개 묶음과 실제 GUI 지형 6개 묶음을 각각 전체 실행해 종료0, 실패0, 생략0을 확인했다. 앞 문단의 4,212항목은 이전 지형 수리 시점의 기록이다. 첫 전체 실행의 저장 검사 시간 초과는 실패로 기록했다. 작업자가 남긴 오래된 검사 프로세스를 정리한 뒤 같은 저장 검사와 전체 33개를 다시 실행해 통과했으며, 시간 초과의 원인을 그 프로세스로 단정하지 않는다.

1707def의 정상 GUI 입력 검사는 자연스럽게 일어서기, 실제 레버 우선 처리, 입력 재설정과 패드 입력 69항목을 종료0으로 확인했다. 실제 핵 살 75셀을 좌클릭으로 먹고 25셀마다 위장 100%에 도달한 뒤 물을 내리지 않고 두 번 토한 검사는 94항목/종료0으로 통과했다. 실제 먹은 300단위가 즉시 핵 6가닥과 공통 2가닥으로 반영됐으며 사망은 없었다. 초기 장면 준비 이후 살·위장·위치를 매 섭취마다 재설정하지 않고 정상 입력과 이동으로 진행했다.

실제 과거 v5 저장의 지형·진행 복원과 두 번의 실제 파일 왕복 161항목, 과거 검사 산출물의 양수 대기 털 및 활성 사망 꾸러미 이관 42항목을 확인했다. 사용자 정상 슬롯은 사용하지 않았다. 양수 자료는 2002246 시점 증거 압축의 실제 검사 저장 파일이며 새로 만든 역사 자료가 아니다. 검사 종료의 ObjectDB/리소스 잔류 경고는 별도로 남아 있다.

정상 Main GUI 연결의 212항목/실패0/종료0은 작성자 실행과 주 담당자의 독립 실행에서 확인했다. 실제 NPC 지급, 발밑 8셀 굴착 후 하강, 전체 캡슐의 짧은 후방 탈출, 실제 신경 접촉에 의한 조직 사망, 새 신경의 굴착 생성·기반 제거, 20초 어둠 뒤 밝은 귀환, 몸·욕조·6방향 외벽을 함께 확인했다. 독립 실행 뒤 변경된 진행 파일은 설명 주석뿐이며 연결 검사 소스도 동일하다.

승인된 Tab 모양은 같은 pitch와 같은 미리보기 후보, 같은 포인터 위치로 과거 실행과 비교해 일치를 확인했다. 후보가 다른 이미지의 머리 모양 차이를 회귀 수리로 기록하지 않는다. 팔 B·피부·방 크기·벨트의 보존 검사 206항목도 통과했다. 과거 자세 비교 검사는 수동 모션 관찰을 사용하므로 정상 Main 입력 검증과 구별한다.

카메라 가드와 가까운 미게시 면의 이전 두 실패는 실제 정상 갱신을 덮는 수동 카메라 설정과 낙하 전 눈 위치를 재사용하는 검사 배치를 바로잡았다. 원래 거리 한계와 패치 선택 assertion을 유지하고, 실제 보정이 필요한 독립 장면 및 한 프레임 더 지난 조준도 확인했다. 관련 굴착 155항목, 고체 조준 67항목, 고체 굴착 143항목이 최종 전체 검사에 포함돼 통과했다. 전체 캡슐 이동 경계의 합벡터 직선 검증은 30항목으로 확인했다.

기획 대조 결과는 [2026-10-06 대조표](design-differences-2026-10-06.md)에 기록했다. 기본 뜯기·큰 톱과 달리 변이 추가 제거 경로의 즉시 표시 연결은 남은 차이이며 이번 적용에 섞어 변경하지 않았다.
