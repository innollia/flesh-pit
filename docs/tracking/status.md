## 2026-10-19 UI·이펙트 다듬기

사용자가 "자잘한 이펙트, 파티클, 화면효과, ui를 다듬어줘. 특히 esc화면, 위장ui는 안예쁘고 이 게임스럽지 않아"라고 했다.

- Esc 화면: 어두운 판과 둥근 버튼을 눈 감기로 바꿨다(spec 08 §1). 눈꺼풀이 0.24초에 닫히고 0.16초에 뜬다. 항목 글씨는 시작 화면의 상자 없는 글씨와 같은 언어다. "계속"은 "눈 뜨기"가 됐다.
- 위장 UI: 기본 글꼴 글자와 9px 막대를 창자 게이지로 바꿨다(spec 01 §4). 초록 웃는 얼굴 토하기 버튼은 게이지 끝의 입이 됐다. 오프닝의 V 안내는 한 번 누르면 사라진다. 매 프레임 다시 켜져 위장 키 표시와 겹쳤기 때문이다.
- 3D 위장 덩어리, 손에 든 뜯긴 살, 들고 다니는 살 더미에 텍스처가 실제로 보인다. 키트의 덩어리 메시에 UV가 없어서 텍스처의 한 점만 찍혔다(`FDKLowPoly.with_box_uvs`).
- 이펙트: 살을 뜯을 때 조각과 핏방울이 튀게 했다. 토사물은 포물선, 착지 담즙, 웅덩이를 갖췄다. 환풍구에 붓는 이빨은 실제 이빨 메시를 쓴다. 죽은 뒤에는 깨어나는 눈꺼풀이 나온다.
- 키 표시: 상호작용 고리, 오프닝, 위장, 키 설정 화면이 같은 이빨색 키캡과 메뉴 글꼴을 쓴다. 자막과 엔딩 크레딧도 메뉴 글꼴을 쓴다.
- 확인: `tests/capture_hud.gd`, `tests/capture_menus_still.gd` 캡처(960×540)로 봤다.
- 이어서 사용자가 "눈 변이마다 다 다른 눈화면"과 키 설정 개편(양방향 화살표, 가운데 주인공의 동작, 그 아래 키 버튼, 옆에서 기다리다 회전하며 바뀌는 다음 사람)을 요청했다.
  - 눈 화면: M24·T5·M03·T1이 각자 다르게 감긴다(spec 08 §1, `tests/capture_eyes.gd`).
  - 키 설정: 회전무대에 지금 몸 6명을 세웠다. 가운데만 동작하고 조명을 받는다(spec 08 §2). 인형은 처음 열 때 만든다(약 80ms). `run_ui_polish_tests.gd`가 회전, 이웃 대기, 짧은 쪽 회전, 키캡 클릭을 확인한다.

## 2026-10-19 최적화와 탱크 들여다보기 조작

사용자가 "폴리곤도 적고 기능도 별거 없는데 랙이 이상하다"고 했다. 같은 플레이를 재생하는 벤치마크(`tests/bench_play.gd`)와 구간 타이머(FPProfile)로 먼저 쟀다. GPU는 1080p에서도 약6ms로 병목이 아니었다. 병목은 CPU의 지형 일이었다.

1280×720 프레임 평균(95%):

| 구간 | 수정 전 | 수정 후 |
|---|---|---|
| 화장실 | 12.2ms (15.4) | 3.9ms (5.3) |
| 문에서 파고 나가기 | 17.2ms (26.1) | 5.2ms (8.1) |
| 판 동굴 | 프레임이 수 초 | 13.2ms (15.0) |
| 긴 통로 | 프레임이 수 초 | 20.7ms (42.7) |

통로·동굴은 벤치마크가 수백 칸을 한 번에 판 직후의 메시화가 대부분이다. 고친 순서와 각각의 근거:

- 화장실에서 매 프레임 청크 하나(약6ms)가 다시 메시화되고 있었다. 재생의 미세 변화는 보일 만큼(0.02) 쌓이거나 표면을 넘을 때만 메시를 더럽히게 했다. 수축은 실제로 조이는 벽 상자가 8m 안일 때만, 3m 밖은 큰 단계로 진행하게 했다. 이것이 대부분이었다.
- 임시 뜯김 면이 판 영역 전체로 커지며 매 프레임 여러 번 전부 다시 만들어지고 있었다. 긴 통로에서 프레임이 수 초가 된 원인이다. 게시된 타일을 하나씩 내리고, 바뀐 타일만 다시 만들고, 프레임 안 반복 갱신을 막았다.
- 압사 판정은 몸에 파고든 살이 없으면 탈출 탐색을 건너뛴다(2.5→0.6ms).
- 재생은 청크마다 여섯 프레임에 한 번 기다린 만큼 자라게 해, 판 양에 비례해 늘던 비용을 1/6로 했다(동굴 5→0.8ms).
- 화면 후처리는 밉맵 생성을 빼 1.1→0.7ms. 그림은 같다(0단계만 읽음).

셰이더를 열화하는 것은 이득이 1ms 남짓이라 하지 않았다. 남은 큰 비용은 청크 하나의 메시 빌드 약6ms(GDScript surface nets)다. 크게 파는 순간과 큰 톱에서 이것이 프레임 튐으로 남는다. 작업량 기준 회귀 검사 `run_perf_budget_tests.gd`를 더했다. 이 과정에서 `run_terrain_solid_dig_tests.gd`의 구멍 벽 충돌 검사가 배치가 빈 바로 그 프레임에 광선을 쏴서 우연에 따라 실패하는 것이 드러났다. 새 충돌체는 다음 물리 단계에 닿는다. 그래서 짧은 한도(30프레임) 안에 벽이 모두 맞는지로 바꿨다.

탱크를 들여다보는 동안 좌우 이동은 머리를 탱크 위로 돌리고, 뒤로 가기나 마구 누르기(1초에 4번)는 고개를 들게 했다. 변기 정산은 겨누지 않고 변기 앞에 서서 F로도 된다.

## 2026-10-19 플레이 피드백: 이빨 집기, 환풍구 말수, 문 눈부심, 끼임

사용자가 플레이 기록(`play_logged.bat`) 뒤 다섯 가지를 지적했다.

- **이빨 집기:** 몸이 변기에 막혀 탱크까지 1.1m에서 멈춰 이빨이 점처럼 보였고, 손에 쥔 이빨이 전혀 보이지 않았다. 이제 열린 탱크에 F를 누르면 고개를 탱크 위로 숙이고(눈이 탱크 입구에서 약 0.45m), 이빨을 하나씩 손바닥에 올린다(F 연속, 우클릭으로 하나씩 도로). 쥔 이빨은 오른손바닥 위의 실제 이빨로 보인다. 손목 회전 한계(±60°) 때문에 손바닥이 위를 향하지 못해, 쥔 동안만 오른손 뿌리를 돌려 손바닥을 위로 했다. 손은 시야 깊이를 당겨 그리므로(squash 0.18), 손바닥의 이빨도 같은 깊이로 그려야 손에 가려지지 않았다. 움직이기, Esc, 다른 곳 보기, 뚜껑 덮기로 끝난다.
- **환풍구 말수:** 말을 고르는 것은 바로 하지만(저장되는 기억), 소리와 자막은 0.7~1.6초 뒤에 나오고 줄 사이는 2.5초 이상이다. 방 안 참견은 15초 조용했을 때만 절반 확률로, 같은 참견은 90초 안에 다시 하지 않는다. 무시당할 때 다시 부르는 간격은 10초다.
- **문 눈부심:** 측정하니 문 밖 1m에서 화면의 84%가 하얗게 날아갔다. 눈 램프만, 문 조명만으로는 각각 5%, 1%였고 둘이 더해질 때 날아갔다. 승인된 문 조명 밝기(0.85)는 방에서 볼 때 그대로 두었다. 대신 눈 램프는 2.5초에 걸쳐 눈이 익으며 켜지고, 열린 문빛 1.8m 안에서는 익지 않는다. 벽이 가까우면, 몸을 비집을수록 램프가 약해진다. 문 조명은 문 바로 밖 빛줄기 안에서만 30%까지 약해졌다가 3m에 걸쳐 돌아온다. 문에서 파고 나가는 실제 입력으로 매 단계 19% 이하다. 문 조명 위치를 방 안으로 0.6m 옮기는 시도는 방 안을 더 밝게 날려서 되돌렸다.
- **끼임과 스페이스 연타:** 눈높이로 판 통로는 바닥이 1m 넘게 높아 걸어 들어갈 수 없었고, 그래서 스페이스로 기어올라야 했다. 키트 컨트롤러가 이제 낮은 턱(0.32m)을 넘고, 길이 이어지는 입구까지 0.9m를 저절로 기어오르며, 천장이 낮으면 고개를 숙이고(키 최저 0.7m), 옆이 좁으면 몸을 뒤틀어(반지름 ×0.6) 실제 캡슐을 줄인다. 가장 비좁을 때 걷기 ×0.35이고, 공간이 생기면 펴진다. 앞의 바닥·천장·폭을 광선 몇 개로 재서 자세를 고르고, 모든 변화는 실제 캡슐 맞춤(`FPBodyClearance.fits`)과 이동 경계를 통과해야 남는다. 막혔는지는 직전 물리 이동이 실제로 간 비율로 판단해 이동 경계 계산을 프레임마다 더 부르지 않는다. 벽에 붙어 미끄러지는 것은 막힘이 아니다. 몸 반경 근처의 가까운 점에서 폭을 재면 스치는 벽을 좁은 틈으로 읽어 몸을 비틀고 미끄러짐을 잃어서, 폭은 먼 점에서만 잰다.
- **위기 연출과 다리:** 비집을수록 시야가 조금씩 좁아지고 떨리며, 세게 비집을 때 젖은 살이 끄는 소리(`squeeze` → `chew_strain`)가 난다. 숨소리 음원이 없어 기존 음원을 썼다. 1인칭 다리(`fp_legs.gd`)를 거울 몸과 같은 비율·피부로 따로 만들었다(거울 몸은 손대지 않음). 무릎이 굽어 발이 바닥에 남고, 걸음을 디디며, 뒤틀면 엉덩이가 돈다. 서서는 배에 가려 보이지 않고 웅크리면 무릎이 보인다.

새 검사는 `run_squeeze_tests.gd`(실제 지형에 판 올라간 통로·낮은 통로·좁은 틈·막다른 벽, 램프·문 조명 포함)와 `run_tank_lean_tests.gd`다. 이 변경으로 깨진 기존 검사 두 가지를 바로잡았다. `run_crush_t8_tests.gd`는 앞 장면에서 걸어 줄어든 몸이 다음 장면에 남아 손으로 넣은 반경 0.46을 무력화했으므로, 장면마다 몸을 원래 크기로 시작하게 했다. `run_restoration_t9_tests.gd`는 첫 대사가 반응 지연 뒤 자막에 닿는지 기다린다. 기준 커밋(`ad13cc0`)에서도 실패하던 것은 그대로다: `run_belt_tests.gd` 3건, `run_revision_tests.gd` 1건, `run_continuation_tests.gd` 스크립트 오류, `run_mutation_tests.gd` 4건, `run_settle_vent_tests.gd` 4건, `run_main_tests.gd` 14건.

## 2026-10-14 보상 척도에 따른 경제 수정

사용자 지시로 이빨은 하나씩 집고 놓는다. 물탱크에서 F 또는 우클릭으로 한 개씩 집고(누르고 있으면 연속), 우클릭으로 한 개씩 도로 넣는다. 환풍구 턱에도 한 개씩 올리며, 손을 멈춘 뒤 0.9초가 지나면 존재가 이번 거래에 낸 합계로 감정한다. 제안 뒤에 더 올리면 제안을 거두고 합계로 다시 본다. 전에는 한 번 올린 줌(최대 4개)마다 따로 감정해서 칼 같은 8이빨 이상 물건에 정상 입력으로 닿지 않았다. 죽을 때마다 시체가 따로 남고 덮어쓰지 않으며, 손과 허리띠에 안 들어가는 것은 그 시체에 남는다. 표시등 불빛은 가까운 8개만 비춘다. 저장에는 시체 목록 전체와, 옛 저장과 맞추기 위한 가장 최근 시체를 함께 남긴다.

보상 척도(09-reward-scale.md) 감사의 위반과 미연결을 고쳤다. 한 셀의 지급은 실제로 줄어든 꼭짓점 밀도를 넘지 않아 다시 차오르는 셀은 차오른 만큼만 준다(보통 뜯기는 그대로 4). 위장은 용량+과식(160)에서, 들기는 들기 용량(40, M13 ×1.5)에서 더 뜯기지 않는다. 몸 반경(M05·T4), 압박 감속(갇혀 압사 시계가 도는 동안 걷기에만, M19·M20), 더미 들고 두 손 도구(M28·T2), T6 이중 적용, M16 정산 크레딧, M15 조건, M17 멍 숨김을 실제로 연결했다. 큰 톱은 들기 모드에서도 위장으로 간다. 소리는 카나리아 지저귐·울음, 수축 예고, 물탱크 달그락, 시작 물소리, 변이 소리 단계를 연결했고 재생 삐걱 소리는 근처에서 실제로 다시 차오르는 뜯긴 자리에서만 난다. 자막은 대기열(최대 3줄)로 덮어쓰지 않는다. 도감 그림은 종류마다 한 장, 기형종은 덤 이빨 4개, 빈 변기 반복 물내림은 존재의 재촉을 다시 시작하지 않으며, 정산이 있으면 레버 직후 저장한다. 가장 바깥 껍질 3m 안까지 간 뒤에는 "마지막 거래"가 열린다. 환풍구 제안의 카나리아 먹이·종양 가방 그림을 따로 만들었다.

경제 수치는 종양을 맨틀·지표면에 하나씩 더해 14개(기존 12개의 위치·번호 유지), 압축 가지 값을 5에서 6으로 올렸다. 척도 감사는 위반 4 → 0, 대역 안 37 → 47이다. 남은 가장 큰 어긋남은 원정 시간 추정이 목표보다 짧다는 것이며, 가격을 부풀리지 않고 실측하기 위해 플레이 기록 장치(FP_PLAY_LOG, `fp_play_log.gd`)를 넣었다. 계산기(tools/economy)는 고친 항목을 코드 근거로 판정하도록 갱신했다.

마지막 동작 수정 뒤 기본 CPU 8개 묶음(655항목)이 실패·생략 없이 종료0으로 통과했다. 별도 실제 GUI 입력은 60항목/종료0이며 V 표시, NPC 지급·수령 및 파일 왕복, 문 다시 닫기, 일어서기, 카나리아 각 단계와 동작 이후 B를 확인했다. 정상 Main GUI 연결 212항목도 종료0으로 통과했으며 어둠 20초 이후 한 번의 밝은 귀환 눈부심과 문턱 왕복 시 추가 눈부심 없음, 실제 신경 조직 사망을 확인했다. 캡슐 압사 47항목, 이동 경계 33항목에서는 실제 짧은 후방 탈출과 전체 압사 제한 시간 이후 생존을 확인했다. 시도했던 압사 조건 완화는 기존 실제 압사 검사를 깨뜨려 철회했다. 원인 불명의 모든 사망 상황이 사라졌다고 이 장면만으로 일반화하지 않는다.

저장 검사 한 번의 180초 시간 초과는 실패로 남긴다. 같은 소스의 단독 저장 검사와 최종 기본 8개 묶음은 각각 종료0으로 재통과했지만 시간 초과의 원인은 특정되지 않았다. 종료 시 기존 ObjectDB/resource 잔류 경고도 남아 있다. 현재 기록은 과거 전체 33개 묶음을 다시 실행했다는 의미가 아니다.

화장실과 인터페이스를 갖춘 굴착 가능한 플레이 버전이다. 먹기·위장·정산·도구·변이·위험·소리·저장·바깥 엔딩의 코드가 있으며, 모든 게임 여정이 이번 검사로 완료 검증된 것은 아니다.

재생 기본률0.003의 연속 회복은 조직·깊이·좁은 통로·스프레이 조합48개에서 이전 대비 고체 기준 도달 시간이3.303~3.338배로 확인됐다. 보호·영구 용해·수축은 유지했다. 방벽 비교359개는 같은 결손과 깊이의 파손 tick이 이전과 같음을 확인했다.

살점 면과 충돌의 방향, 공유 청크·음수 경계·미게시 표면·완전 고체 내부 표시가 수리됐다. 정상 Main의 일곱 방향에서 각각 실제 연속 좌클릭으로 두 번씩 뜯고 밀도·섭취·놓기와 화면 누출0을 확인했다. 문 앞의 실제 F·좌클릭·W 이동과 재생중 연속 프레임도 통과했다. 실제 과거 v5 저장을 압축 fixture에서 복원한664개 검사와 첫10렌더프레임의 외부 누출0을 확인했다.

승인된 팔 B 자세·오른팔 퇴장·엄지·어깨 연결, Tab0.20과 카메라 정렬, 기존 문 판정·화장실 크기·피부·벨트 스프레이 그림자 조건을 보존 검사로 확인했다. 과거 부품을 확인하던 검사 한 항목은 현재 승인된 부품에 맞췄으며 게임 자세를 변경하지 않았다.

Intel UHD770,640×360,361프레임 문 앞 굴착에서 제한 해제 프레임 중앙값8.230ms/p9511.239ms다. 연결 수리 직후의p9524.520ms보다 줄었지만 과거 지형의p958.834ms보다 높다. 실제 연결·임시 면의 추가 비용을 포함하며 장시간·다른 장비의 성능 보장은 아니다.

남은 검증은 원정3~5분·전체4~6시간 목표에 맞는 경제와 귀환 긴장, 전 껍질 탐색과 모든 도구·변이 조합, 최종 엔딩의 긴 플레이 흐름이다. 이 항목은 별도 플레이 검증이며 이번 세 결함 수리에서 게임 전체 밸런스를 완료했다고 취급하지 않는다.

앞선 세 가지 지형 결함 수리 당시 통합 코드에서 node --test game/tests/run_godot_checks.cjs의 지형·기존 보존20개 묶음(4,212항목)과 node --test game/tests/run_godot_render_checks.cjs의 실제 렌더링6개 묶음이 모두 종료0으로 통과했다. 렌더링은 내부·경계·미게시·재생·과거 저장과 정상 입력을 함께 확인했다.

## 화장실 정상 플레이 복원 검증

복원 코드 1707def에서 최종 CPU 33개 묶음과 실제 GUI 지형 6개 묶음을 각각 전체 실행해 종료0, 실패0, 생략0을 확인했다. 앞 문단의 4,212항목은 이전 지형 수리 시점의 기록이다. 첫 전체 실행의 저장 검사 시간 초과는 실패로 기록했다. 작업자가 남긴 오래된 검사 프로세스를 정리한 뒤 같은 저장 검사와 전체 33개를 다시 실행해 통과했으며, 시간 초과의 원인을 그 프로세스로 단정하지 않는다.

1707def의 정상 GUI 입력 검사는 자연스럽게 일어서기, 실제 레버 우선 처리, 입력 재설정과 패드 입력 69항목을 종료0으로 확인했다. 실제 핵 살 75셀을 좌클릭으로 먹고 25셀마다 위장 100%에 도달한 뒤 물을 내리지 않고 두 번 토한 검사는 94항목/종료0으로 통과했다. 실제 먹은 300단위가 즉시 핵 6가닥과 공통 2가닥으로 반영됐으며 사망은 없었다. 초기 장면 준비 이후 살·위장·위치를 매 섭취마다 재설정하지 않고 정상 입력과 이동으로 진행했다.

실제 과거 v5 저장의 지형·진행 복원과 두 번의 실제 파일 왕복 161항목, 과거 검사 산출물의 양수 대기 털 및 활성 사망 꾸러미 이관 42항목을 확인했다. 사용자 정상 슬롯은 사용하지 않았다. 양수 자료는 2002246 시점 증거 압축의 실제 검사 저장 파일이며 새로 만든 역사 자료가 아니다. 검사 종료의 ObjectDB/리소스 잔류 경고는 별도로 남아 있다.

정상 Main GUI 연결의 212항목/실패0/종료0은 작성자 실행과 주 담당자의 독립 실행에서 확인했다. 실제 NPC 지급, 발밑 8셀 굴착 후 하강, 전체 캡슐의 짧은 후방 탈출, 실제 신경 접촉에 의한 조직 사망, 새 신경의 굴착 생성·기반 제거, 20초 어둠 뒤 밝은 귀환, 몸·욕조·6방향 외벽을 함께 확인했다. 독립 실행 뒤 변경된 진행 파일은 설명 주석뿐이며 연결 검사 소스도 동일하다.

승인된 Tab 모양은 같은 pitch와 같은 미리보기 후보, 같은 포인터 위치로 과거 실행과 비교해 일치를 확인했다. 후보가 다른 이미지의 머리 모양 차이를 회귀 수리로 기록하지 않는다. 팔 B·피부·방 크기·벨트의 보존 검사 206항목도 통과했다. 과거 자세 비교 검사는 수동 모션 관찰을 사용하므로 정상 Main 입력 검증과 구별한다.

카메라 가드와 가까운 미게시 면의 이전 두 실패는 실제 정상 갱신을 덮는 수동 카메라 설정과 낙하 전 눈 위치를 재사용하는 검사 배치를 바로잡았다. 원래 거리 한계와 패치 선택 assertion을 유지하고, 실제 보정이 필요한 독립 장면 및 한 프레임 더 지난 조준도 확인했다. 관련 굴착 155항목, 고체 조준 67항목, 고체 굴착 143항목이 최종 전체 검사에 포함돼 통과했다. 전체 캡슐 이동 경계의 합벡터 직선 검증은 30항목으로 확인했다.

기획 대조 결과는 [2026-10-06 대조표](design-differences-2026-10-06.md)에 기록했다. 기본 뜯기·큰 톱과 달리 변이 추가 제거 경로의 즉시 표시 연결은 남은 차이이며 이번 적용에 섞어 변경하지 않았다.
