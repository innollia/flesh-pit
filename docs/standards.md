# 구현 경계와 확인 조건

게임의 화장실·진행·입력·저장 연결은 game/main이 맡고 재사용 Kit가 Main을 import하지 않는다. game/audio의 연결은 상태 읽기와 신호 구독으로 한정한다. 지형 전용 렌더링 수리가 공통 피부·손·가구 셰이더까지 바꾸면 경계를 위반한다.

메시와 충돌은 같은 실제 삼각형을 사용한다. 청크 경계의 제거는 인접 공유 밀도까지 반영하며, 연결된 갱신은 같은 스냅샷을 게시한다. 내부 표시 헬퍼는 실제 밀도 또는 게시된 표면에서 면을 생성한다. 실제 수정 상태와 분리된 판정 전용 가짜 살점은 허용하지 않는다.

일반 굴착은 제한된 청크·시간 예산으로 갱신한다. 복원 시 한 번 전체 표시를 준비하는 것과 매 프레임 또는 매 뜯기마다 전체 세계를 다시 만드는 것은 다르다. 예산 때문에 다음 프레임으로 넘긴 작업은 연속 재생 중에도 완료되어야 한다.

검사는 자신의 종료 코드를 전달하고 실제 통과 결과를 확인한다. 스크립트 오류·시간 초과·빈 결과는 통과가 아니다. GUI 검사는 실제 해상도와 입력·정상 갱신을 확인한다. 카메라 보정의 이중 호출이나 수동 상태 진행으로 정상 게임의 성공을 대신하지 않는다.

기존 기능을 되돌리는 요청은 과거 구현과 승인된 수정의 차이를 기준으로 처리한다. 저장·손 자세 등 관련 회귀 검사를 삭제하거나 생략하여 통과시키지 않는다. 작업 범위 밖의 파일 변화는 소유와 필요성이 확인된 경우에만 포함한다.
