# 소리와 음악

## 음악 기준

사용자가 2026-11-07에 정한 기준이다. 곡을 넣거나 옮길 때 이 표로 판단한다.

| 규칙 | 뜻 |
|---|---|
| 음악은 플레이어가 아는 상태를 말한다 | 곡이 알려 주는 것은 플레이어도 아는 상황이어야 한다 |
| 같은 상태면 같은 곡이다 | 같은 상황에서 곡이 달라지지 않는다 |
| 바뀌는 이유를 짐작할 수 있어야 한다 | 까닭 없이 곡이 바뀌지 않는다 |
| 시선 방향으로 바꾸지 않는다 | 고개를 돌렸다고 곡이 바뀌지 않는다 |
| ~~파는 동안 음악은 없다~~ | 2026-11-07에 뒤집혔다("살 팔때도 음악 들리기"). 아래 "살 속 음악" |
| Esc는 눈을 감은 곳으로 곡을 고른다 | 화장실은 `mus_pause_alt`, 살 속은 `mus_pause`. 무작위 없음 |

화장실 음악은 끊기지 않는 상태 기반 체계로 만든다. 환풍구 대사처럼 상황에 대응한다.

## 현재 곡 배치

`game/audio/fp_music.gd`가 게임 상태만 읽어 곳을 정한다. 곳이 바뀌면 2.5초에 걸쳐 섞고, 살로 나가면 0.8초 안에 사라진다. 모든 곡은 Music 버스이고 설정의 배경음이 음량을 정한다.

| 곳 | 곡 | 느낌 |
|---|---|---|
| 시작 화면 | `mus_title` | 음이 어긋난 오르골 자장가와 낡은 리드 오르간 |
| 키 설정 | `mus_keybind` | 유원지 오르간 왈츠 |
| Esc, 살 속 | `mus_pause` | 녹아 넘어가는 따뜻한 현악 패드, 박 없음 |
| Esc, 화장실 안 | `mus_pause_alt` | 펠트 피아노. 끌 때까지 바뀌지 않는다 |
| 환풍구가 열려 있는 동안 | `mus_vent` | 휘파람과 걷는 저음 |
| 방 안의 변이 화면 | `mus_mirror` | 7/8박 신스와 손목시계 소리 |
| 화장실과 변기 정산 | `mus_room_*` 여덟 층 | 한 곡이다. 상황에 따라 층의 음량만 움직인다(`game/audio/room_music.json`) |
| 살 속(껍질마다), 살 속의 Tab | `mus_flesh_core`·`mus_flesh_mantle`·`mus_flesh_surface` | 아래 "살 속 음악" |
| 쉼터(살 속 컨테이너) | 없음. 곡이 4초에 걸쳐 사라지고 쉼이 시작된다 | |
| 엔딩 | 엔딩 노래 층만 | 아래 항목 |

설정 화면은 연 화면의 곡을 잇고, 변기에 앉기와 도감에는 곡이 없다.

옛 `mus_restroom`과 `mus_settle`은 없어졌고, `mus_settle`은 `mus_room_reckon` 층이 됐다. 화장실 층은 시선을 보지 않으며, 많이 파고 돌아오면 무서운 `mus_room_dread` 층이 올라온다. 사람이 들어 보지 않았다.

후보 6곡(감정, 아트 스타일, 재료, 반복 구조, 이야기, 역설) 가운데 감정·재료·반복 구조는 살 속 곡이 됐다(아래). 나머지는 넣지 않았고 `build/music_lab.html`에 모았다. 패치와 만드는 스크립트는 `game/tools/audio/lab/`에 있다. 사용자 반응(2026-11-07): 감정·아트 스타일·재료·반복 구조가 좋다. 아트 스타일은 신나고 전자적이라 유기물 느낌으로 고쳐야 넣는다. 역설은 트레일러용이다. `mus_pause_alt`와 감정(`lab_emotion`)은 새 곡의 기준점이다.

## 살 속 음악

사용자가 2026-11-07에 "살 팔때도 음악 들리기"라고 했다. `game/audio/fp_flesh_music.gd`가 게임 상태만 읽어 곡을 고르고, 수치는 `game/audio/flesh_music.json`에 있다. 사람이 들어 보지 않았다.

| 곳 | 곡 | 원래 후보 |
|---|---|---|
| 핵(0번 껍질) | `mus_flesh_core` | `lab_emotion`, 3/4 자장가. 역겨움이 식욕으로 미끄러진다 |
| 맨틀(1번 껍질) | `mus_flesh_mantle` | `lab_materials`, 물방울·타일·배관·고기·이·숨·변기 테로 짠 7/8 그루브 |
| 겉껍질(2번 껍질) | `mus_flesh_surface` | `lab_cycle`, 뜯기·씹기·삼키기·토하기, 144 BPM |

- 상태는 껍질이다. 껍질 사이에는 파고 지나가야 하는 막이 있고, 칼이 필요한 곳이 맨틀부터이며, 정산도 껍질로 값을 매기므로 플레이어가 어느 껍질인지 안다. 바깥으로 갈수록 곡이 진해진다(자장가 → 재료 그루브 → 먹기 순환). 바이옴은 쓰지 않았다. 껍질마다 여러 개이고 배경 묶음이 다섯이라 세 곡과 짝이 맞지 않으며, 바이옴 경계는 걸어서 쉽게 넘나들어 곡이 자주 바뀐다. 위험(조임, 재생)도 쓰지 않았다. 그때는 경고음이 읽혀야 하므로 곡이 바뀌어 시선을 끌면 안 된다.
- 같은 껍질이면 같은 곡이다. 시선, 바이옴, 무작위는 곡을 바꾸지 않는다.
- 껍질이 바뀌면 지금 곡이 다음 마디 표시(`phrases`, 감정·재료는 4마디=10초, 반복 구조는 뜯기·씹기·삼키기·토하기 구간의 시작)까지 가고, 그때 3초에 걸쳐 새 곡이 처음부터 섞여 들어온다. 표시 전에 되돌아가면 아무것도 바뀌지 않는다.
- 긴 원정이 지치지 않도록 곡은 한 바퀴(약 100초)만 돌고 마지막 8초에 걸쳐 사라진 뒤 75초 쉰다. 쉼에는 몸 소리와 엔딩 노래의 희미한 선율만 있다. 쉼 동안 다른 껍질로 넘어가면 그 껍질의 곡이 바로 시작한다(플레이어가 막을 뚫었다는 것을 안다). 같은 껍질이면 쉼이 끝날 때 같은 곡이 처음부터 다시 시작한다. 약 175초마다 100초, 음악이 시간의 57%를 차지한다.
- 쉼터 컨테이너에 들어가면 그것이 쉼이다. 곡이 4초에 걸쳐 사라지고 그 껍질의 쉼이 시작된다.
- Esc와 키 설정에서는 2.5초에 걸쳐 사라지고 `mus_pause`가 들어온다(Esc 규칙은 그대로). 눈을 뜨면 멈춘 자리에서 같은 곡이 다시 올라온다. 살 속의 Tab은 곡을 그대로 둔다.
- 화장실, 엔딩, 시작 화면에서는 2초에 걸쳐 사라진다. 화장실 음악(`fp_music.gd`, `room_music.json`)은 바꾸지 않았다.
- 엔딩 노래 층 `song_melody`는 곡의 쉼을 채운다. 곡이 올라온 만큼 선율이 물러나고(`1 - 곡 음량`), 쉼과 쉼터에서는 전처럼 바깥으로 갈수록 커진다(최대 0.35). 두 곡이 조가 달라 겹치면 부딪치기 때문이다.

## 배경 소리

`game/audio/manifest.json`의 `beds`가 묶음이고 `fp_audio_hookup.gd`가 위치로 고른다. 살 속 묶음은 몸 층이나 바이옴 층에 심장을 쌓는다.

| 묶음 | 층 |
|---|---|
| `restroom` | 형광등 웅웅(`amb_restroom`), 낡은 환풍기(`amb_restroom_fan`) |
| `body_a`, `body_b` | 몸 소리와 심장 |
| 지방 동굴, 연골 궁륭, 위벽 주름, 옷 뭉치, 털 덤불 | 자기 바이옴 층과 심장 (몸 층은 빠짐) |

- 화장실은 자기 숨소리가 들릴 만큼 조용해야 한다. 문, 물 내림, 환풍구 소리를 가리지 않는다.
- 벽 속 물소리는 반복이 없다. 네 종류의 단발이 45~150초 간격으로, 방에 들어온 뒤 첫 번은 25~70초 뒤에 난다(`fp_pipe_water.gd`).
- 심장은 노트북 스피커에서 들려야 한다. `amb_heart_a`, `amb_heart_b`는 170~300 Hz에 박동을 뒀다.
- 몸과 바이옴 층은 2026-11-07에 nkido로 다시 만들었다. 층 위에 단발 13종(`fp_body_events.gd`, 각 4변주)이 불규칙하게 나고, 위치 있는 단발은 실제 벽에서 난다. 사람이 들어 보지 않았다.

## 효과음

효과음과 언제 나는지의 목록은 `game/audio/SOUND_LIST.md`가 맡는다. 가깝고 젖은 몸 소리를 쓰고, 변이는 숫자보다 먼저 플레이어 자신의 소리를 바꾼다. M03 윙 소리는 음악이 아니라 화장실 쪽을 볼 때 나는 변이의 소리다.

### 발소리와 뜯기의 방

사용자가 2026-11-08에 "발소리 등 몇몇 소리가 이전보다 안 좋아짐.(아케이드같아졌음)"이라고 했다. 발소리 파일은 2026-09-30(PS1 질감) 뒤로 바뀌지 않았다. 바뀐 것은 둘레다. 2026-11-07 살 속 배경을 다시 만들면서 배경이 4~7 dB, 발소리 대역(1~6 kHz)에서 6~10 dB 조용해졌고, 곡이 오르면 6 dB 더 내려간다. 발소리 자기 대역 여유가 예전 배경에서 −2.5~−8 dB(배경에 묻힘)였는데 +0.7~+9 dB(배경 위에 혼자 섬)가 됐다. 그러자 예전에 묻혀 있던 PS1 처리(16 kHz 샘플앤홀드, 10비트, 19/27/41 ms 금속 콤 울림), 사인파 쿵(95 Hz), 좁은 대역(Q 12) 찍찍임, 타일의 60 ms 한 번 메아리, 매번 같은 높이·세기가 드러났다.

2026-11-08(round7-sfx)에 고친 것:
- 발소리 6종을 nkido 패치로 다시 만들었다. 사인파 대신 저역 통과 잡음으로 무게, 넓은 대역의 철벅임, 젖은 똑똑임, 타일은 넓은 대역 밑창 소리와 긁힘. PS1 처리는 껐다. `step_flesh_s2`에 진창 녹음 층을 더했다. 다시 만들기: `python -X utf8 tools/build_sfx_only.py step_flesh_s1 ...`(manifest와 반복음은 그대로).
- 발소리와 뜯기는 Room 버스(짧은 잔향, SFX로 보냄)에서 난다. 화장실은 타일 방(room 0.34, damping 0.4, wet 0.2), 살 속은 작고 먹먹한 방(0.2, 0.85, 0.16). 씹기와 삼키기는 머릿속 소리라 그대로 마른 소리다.
- 걸음마다 높이 ±4%, 세기 ±1.5 dB, 뜯기마다 높이 ±3%가 달라진다. 살 속 발소리는 3 dB 낮췄다.

측정(사람이 들은 것이 아니다): 소리 높이 뚜렷함(정점 뒤 50 ms 자기상관 최대) 가장 높은 발소리 0.55(step_tile_s2) → 0.24, step_flesh_s2 0.51 → 0.15. CLAP의 "아케이드/8비트/비트크러시/삐" 몫은 step_tile_s1 0.56 → 0.08, step_tile_s2 0.29 → 0.04, step_flesh_s2 0.24 → 0.001. 곡 있는 살 속 발소리 자기 대역 여유(파일 기준)는 4.2~9.9 dB이고 실제로는 3 dB 낮은 1.2~6.9 dB다. 씹기·조임 경고·뜯기·삼키기 여유는 바뀌지 않았다. 엔진 녹음은 `game/tests/capture_steps.gd`, 비교는 `tools/measure_steps.py`, `tools/clap_arcade.py`.

CLAP이 아직 아케이드 쪽으로 보는 소리: regen_creak(1.0, 경고음이라 손대지 않음). tear_fat·nerve_twitch·tear_flesh는 아래 round8에서 다시 만들었다. regen_creak는 2026-11-14에 톱니파와 좁은 대역을 빼고 다시 만들었고 CLAP은 아직 다시 재지 않았다(아래 "한 입과 조임의 새 소리").

### 한 입과 조임의 새 소리 (2026-11-14)

한 신호가 한 뜻만 지도록 음원을 나누고 게임에 연결했다. 목록·경로·측정값은 `game/audio/SOUND_LIST.md`. 사람이 들은 것은 아직 없다.
- 수축 예고는 contract_warn(낮게 차오르다 멈춤), 재생은 regen_creak(불규칙한 젖은 알갱이)로 갈랐다. 둘은 긴 시간 스펙트럼이 가까워(거리 5.6 dB) 모양과 음량으로 구별된다.
- 끼임은 squeeze_breath(코로 밀려 나오는 짧은 날숨), 압사는 crush_breath(얕고 빠른 숨의 반복음)다. 과식 신음 chew_strain과 다른 소리다.
- 가득 찬 위장의 거절은 full_refuse(다문 입의 "읍"과 마른 트림)다. gag_dry는 밖에서 못 토하는 헛구역질 한 뜻만 진다.
- 조직 뜯김: 수축 tear_muscle, 연골 tear_cartilage, 옷 tear_cloth, 털 tear_hair.

연결한 방식(`game/audio/fp_audio_hookup.gd`, 키트 `fdk_audio_director.gd`):
- 수축 예고는 플레이어에게 가장 가까운 조이는 모서리의 조임 1.3초 전에 그 모서리 자리에서 contract_warn이 난다(청크마다 하나)(소리는 0.86초에 끝나 조임 시작 전에 멈춘다). regen_creak는 재생에서만 난다.
- 재생 삐걱임은 배경과 상관없이 살 속 어디서나 난다(바이옴 포함, 화장실·쉼터·엔딩 제외). 8 m 안의 뜯은 자리 가운데 아직 열려 있고 닫힘에 가장 가까운 곳(밀도 0.15~닫힘 기준 사이에서 가장 높은 곳)에서 나고, 그 가까움(0~1)에 따라 간격이 5~12초에서 1.5~3초로, 음량이 −6 dB에서 0 dB로 간다. 소리는 방금 뜯은 앞이 아니라 닫히는 등 뒤에서 난다.
- 끼임 이벤트는 squeeze_breath다. crush_breath는 SFX 버스의 상시 층으로 음량이 `main.crush_progress()`를 따르고 재생 속도가 0.9 → 1.25로 빨라진다. 벗어나면 진행과 같이 빠진다. 압사 중에 곡 음량은 건드리지 않는다(음악은 위험을 쓰지 않는다).
- full_refuse는 `Main.stomach_refused`에 붙였다(게임이 0.9초에 한 번으로 줄여 낸다). 삼킴은 뜯김 0.3초 뒤 그대로다.
- pull_stretch는 Room 버스의 상시 층이다. 씹기 진행 r에 음량 −30 → −6 dB(r 제곱), 높이 0.85 → 1.15로 움직이고 뜯김과 놓기에서 바로 꺼진다. 뜯김은 실제로 뜯긴 양(한 칸 대비 u)에 따라 −8 → 0 dB, 높이 ×(1 + 0.08 × (1 − u))다.
- 발소리는 몸이 직전 걸음 뒤로 수평 0.12 m 넘게 움직였을 때만 난다. 막힌 1칸 굴에서 걷는 소리가 나지 않는다.
- 다시 재야 하는 것: 삐걱임이 잦아졌으므로 `tools/measure_beds.py`의 재생 삐걱·조임 경고 열(새 id가 manifest에 들어갔다), CLAP 아케이드 몫.
- 한 입의 당김 pull_stretch는 고른 결의 반복음이고, 음량과 높이는 연결 쪽이 chew_progress로 움직인다.

수치만 쟀고 사람이 들어 보지 않았다.

### 문, 칼로 뜯기, 레버 물 내림 (round8-sfx, 2026-11-09)

사용자가 2026-11-09에 "문열리는 소리 이상함", "살 뜯을때 철컥 탕 소리는 총쏘는거잖아", "변기 물내릴때 소리가 카나리아 비명지르는거랑 유사함"이라고 했다. 실제로 나는 소리를 연결에서 찾아 쟀다.
- 문 열기는 화장실 `is_door_open`이 바뀔 때 hookup이 내는 door_open 하나다. 1.8 kHz 사인 딸깍, 30→75 Hz 톱니를 Q 6의 950 Hz 대역에 통과시킨 삐걱, 70 ms 메아리 한 번이었다. 가장 센 음정선이 주변보다 19 dB 높았다. 이제 걸쇠·무게는 잡음, 경첩은 CC0 문 삐걱 녹음(`s5/bss0616`)을 0.8배로 낮춰 변주마다 다른 구간을 쓴다(음정선 5~10 dB). door_close는 말이 없어서 그대로 뒀다.
- 칼을 든 손으로 뜯으면 키트 디렉터의 tear_*와 `scissors_snipped`의 scissors_snip이 같은 프레임에 난다. scissors_snip은 마른 가위 녹음 1.2초(금속 딸깍 네 번, 네 변주가 같은 녹음)였고 tear_flesh에는 4 ms 어택의 58 Hz 사인 쿵이 있었다(150 Hz 아래가 최대치의 −7 dB). 철컥 + 탕이다. 이제 칼은 젖은 찢김과 진창 녹음으로 살을 자르는 소리이고, tear_flesh는 사인·톱니 없이 찢김 녹음(`tear/fs133440`)과 진창 철벅임(`mud/fs0495`)이 변주마다 다른 구간으로 나고 잡음 섬유가 밑에 깔린다. tear_fat(95 Hz 사인·Q 7)과 nerve_twitch(삼각파·65 Hz 사인)도 같은 식으로 고쳤다. saw_stroke는 사람 말이 없고 CLAP이 실제 녹음으로 봐서(0.01) 그대로다.
- 레버를 당기면 toilet_flush와 물탱크 달그락이 같이 난다. 달그락은 coin_drop(2.1/3.4/5.2 kHz 사인 팅, 음정선 30 dB)을 0.22~0.45초마다 다시 냈고 canary_chirp가 3.4 kHz다. 물 내림 녹음은 3초부터 잘라 써서 물탱크가 쉭 차오르는 부분(2.5 kHz 위가 85 ms 창의 76 %)이 들어 있었다. 이제 달그락은 자기 소리 teeth_rattle(떨어지는 돌 녹음을 1.6 kHz 아래로, 음정 없음)이고, 물 내림은 녹음의 처음 3초(쏟아짐)와 끝의 꾸르륵, 2 kHz 아래의 잡음 배관이다.

측정(사람이 들은 것이 아니다, `tools/measure_sfx_char.py`, `tools/mix_sfx_chains.py`, `tools/clap_arcade.py`): 엔진 녹음(`game/tests/capture_round8_sfx.gd`)에서 문 열기 음정선 19.2 → 7.1 dB, 레버 묶음 음정선 15.4 dB(3.5 kHz) → 7.5 dB, 2.5 kHz 위 몫 −2.6 → −8.6 dB. CLAP "작은 새" 몫은 레버 묶음 0.24 → 0.00, "고무 장난감"은 문 0.995 → 0.38, 아케이드 몫은 tear_fat 0.99 → 0.62, nerve_twitch 0.99 → 0.56, tear_flesh 0.77 → 0.51. 칼 묶음은 "총" 0.10 → 0.09, 아케이드 0.90 그대로다(`docs/tracking/findings.md`). tear_fat의 배경 위 자기 대역 여유는 가장 나쁜 곳에서 6~10 dB → 1~3 dB(여전히 배경 위)로 줄었다. 좁게 울리던 대역이 넓은 녹음으로 바뀐 값이다.

`real_layer`는 이제 목록(여러 녹음을 더함)과 `offsets_s`(변주 후보마다 다른 구간), `follow_pitch`(후보의 높이를 녹음에도), `delay_s`를 받는다(`build_audio.load_real_layer`). 이런 소리는 녹음을 섞은 뒤 변주를 고른다.

## 엔딩 노래

층 넷이 게임이 보고하는 값을 따른다(`fp_audio_hookup.gd`). 엔딩에서 허밍이 곡을 맡고, 종양 도감을 다 채우면 목소리가 한 겹 더해진다(`song_voice2`).

`song_melody`는 살 속에서 바깥으로 갈수록 희미하게 커진다(`main.melody_level`, 최대 0.35). 곡이 아니라 엔딩 노래를 미리 흘려 주는 층이며, 살 속 곡이 생긴 뒤에는 곡의 쉼과 쉼터에서 들린다(위 "살 속 음악").

## 소리의 분리

소리 연결은 상태를 읽고 신호를 받을 뿐 진행을 바꾸지 않는다(`game/audio/AGENTS.md`).

## 만드는 법과 확인

- 음악과 소리는 nkido 패치로 만든다(`game/tools/audio/patches/*.akkado`, `tools/build_music.py`, `tools/render_loop_patches.py`). 파이썬은 믹스, 페이드, 측정에만 쓴다. `mus_title`처럼 이전에 만든 곡 일부는 파이썬 합성으로 남아 있다.
- 모아 듣기: `py -3 -B tools/build_sound_gallery.py`가 후보곡 묶음까지 포함한 `build/sound_gallery.html`을 만든다.
- 수치, 스펙트로그램, 판별 모델의 판정은 사람이 들어 본 것이 아니다. 보고할 때 구분해서 적는다.
